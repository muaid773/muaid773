# دليل بيانات المشاريع

`data/projects.json` هو المصدر الوحيد لبطاقات المشاريع وتفاصيلها. الملف مصفوفة JSON عادية؛ لا تضع فيه تعليقات أو فاصلة بعد العنصر الأخير. العقد الرسمي موجود في `data/projects.schema.json`، والبناء يفحص الحقول ومسارات الملفات قبل نسخ الموقع إلى `dist/public`.

## إضافة مشروع

1. أنشئ مجلدًا باسم المعرّف داخل `assets/projects/`، مثل `assets/projects/inventory-dashboard/`.
2. أضف الصور والفيديو والترجمة إلى ذلك المجلد.
3. أضف كائن المشروع إلى المصفوفة في `data/projects.json`.
4. شغّل `pnpm --filter @workspace/developer-portfolio run validate:projects`، أو نفّذ البناء؛ البناء يشغّل الفاحص تلقائيًا.

هذا مثال يوضح جميع الحقول الأساسية والاختيارية:

```json
[
  {
    "id": "inventory-dashboard",
    "title": "لوحة إدارة المخزون",
    "description": "لوحة تساعد فريقًا صغيرًا على متابعة المخزون والطلبات من مكان واحد. أضف هنا المشكلة التي يحلها المشروع والنتيجة الفعلية التي حققها.",
    "role": "تصميم بنية البيانات وبناء واجهة الإدارة وواجهات API",
    "year": 2025,
    "status": "live",
    "category": "web",
    "platform": "web",
    "technologies": ["Python", "FastAPI", "JavaScript"],
    "thumbnail": "assets/projects/inventory-dashboard/cover.webp",
    "media": [
      {
        "type": "image",
        "src": "assets/projects/inventory-dashboard/dashboard.webp",
        "alt": "لوحة المخزون تعرض الأصناف ومستويات الكمية",
        "caption": "الشاشة الرئيسية لإدارة المخزون"
      },
      {
        "type": "video",
        "src": "assets/projects/inventory-dashboard/walkthrough.mp4",
        "alt": "جولة قصيرة توضح إضافة صنف ومتابعة الكمية",
        "caption": "جولة في تدفق إدارة الصنف",
        "poster": "assets/projects/inventory-dashboard/walkthrough-poster.webp",
        "captions": "assets/projects/inventory-dashboard/walkthrough.ar.vtt",
        "captionsLanguage": "ar"
      }
    ],
    "links": {
      "demo": "https://example.com",
      "repository": "https://github.com/username/inventory-dashboard"
    },
    "featured": true,
    "order": 1
  }
]
```

استبدل كل النصوص والروابط في المثال بمعلومات حقيقية. لا تستخدم أرقام نتائج أو شعارات عملاء أو روابط تجريبية في موقعك المنشور.

## الحقول

| الحقل | مطلوب | القاعدة |
|---|---:|---|
| `id` | نعم | معرّف فريد بحروف إنجليزية صغيرة وأرقام وشرطات، مثل `inventory-dashboard`. |
| `title` | نعم | اسم قصير وواضح للمشروع. |
| `description` | نعم | وصف واقعي من 20 إلى 600 حرف يشرح المشكلة والحل والنتيجة، لا قائمة تسويقية عامة. |
| `role` | لا | مساهمتك أنت تحديدًا، وميّزها عن عمل الفريق إن وُجد. |
| `year` | لا | سنة العمل على المشروع. |
| `status` | لا | واحدة من `live` أو `completed` أو `in-progress` أو `archived`. |
| `category` | نعم | `web` أو `mobile` أو `desktop` أو `backend` أو `bots` أو `automation` أو `other`. |
| `platform` | نعم | `phone` أو `tablet` أو `desktop` أو `web`. |
| `technologies` | نعم | مصفوفة تقنيات؛ اذكر ما استخدمته فعلًا فقط. |
| `thumbnail` | لا | صورة البطاقة قبل فتح التفاصيل. |
| `media` | نعم | قائمة مرتبة من الصور والفيديوهات؛ استخدم `[]` إن لم تتوفر وسائط. |
| `links` | لا | رابط `demo` و/أو رابط `repository`، ويجب أن يكونا HTTP أو HTTPS. |
| `featured` | نعم | `true` لإبراز المشروع أو `false` لغير ذلك. |
| `order` | نعم | عدد صحيح غير سالب؛ الأصغر يظهر أولًا في ترتيب JSON. |

### عناصر الوسائط

- الصورة: `type`, `src`, `alt` مطلوبة؛ `caption` اختياري. اكتب في `alt` ما توضحه الصورة، لا عبارة عامة مثل "صورة المشروع".
- الفيديو: `type`, `src`, `alt` مطلوبة؛ `caption`, `poster`, `captions`, و`captionsLanguage` اختيارية.
- أضف عناصر `media` بالترتيب الذي تريد أن يتصفحها الزائر. تظهر الصور المصغرة، نوع الملف، الوصف، وعدّاد العنصر. يستطيع الزائر فتح/تنزيل الملف الأصلي.
- عند إضافة `captions`، استخدم ملف WebVTT بامتداد `.vtt`. اللغة الافتراضية للعناوين هي `ar`؛ غيّر `captionsLanguage` عند استخدام لغة أخرى.

### الملفات المدعومة

- الصور: `.jpg`, `.jpeg`, `.png`, `.webp`, `.gif`.
- الفيديو: `.mp4`, `.webm`, `.ogv`. يوصى بـ MP4 بترميز H.264 للصوت والصورة للتوافق الواسع.
- الترجمات: `.vtt`.
- يجب أن تكون مسارات الوسائط محلية وتبدأ بـ `assets/projects/`. لا تستخدم روابط خارجية للوسائط، ولا `..` أو مسارات مطلقة. الروابط الخارجية توضع في `links`.
- استخدم اسم مجلد مطابقًا لـ `id`، وأسماء ملفات إنجليزية قصيرة مثل `screen-01.webp` و`walkthrough.mp4`. استخدم أحرفًا لاتينية وأرقامًا ونقطة وشرطة أو شرطة سفلية فقط؛ لا تستخدم مسافات.

## كتابة وصف مقنع وصادق

اتبع هذا الترتيب في `description`:

1. **المشكلة:** ما الحاجة أو العمل المتكرر الذي استهدفه المشروع؟
2. **الحل:** ما الوظيفة التي بنيتها؟
3. **دورك:** ما الجزء الذي أنجزته بنفسك؟ استخدم `role` لتحديد ذلك بوضوح.
4. **النتيجة:** اذكر أثرًا يمكن التحقق منه إن وُجد؛ لا تخترع أرقامًا.

أبقِ الوصف موجزًا. ضع تفاصيل التقنية في `technologies`، ولقطات الشاشات والفيديو في `media` بدل حشرها كلها في فقرة واحدة.

## قواعد JSON والتحقق

- استخدم علامات اقتباس مزدوجة `"`، ولا تضف فاصلة بعد آخر عنصر.
- ضع فاصلة بين المشاريع داخل المصفوفة، ولا تحذف الأقواس `[` و`]`.
- لا تكرر `id`، ولا تضف مفاتيح خارج المخطط. إذا احتجت حقلًا جديدًا مستقبلًا، حدّث المخطط والدليل والفاحص معًا.
- الفاحص يتأكد من أسماء الحقول، الأنواع والقيم، فرادة المعرّفات، امتدادات الوسائط، ووجود الملفات على القرص.
- جرّب التحقق يدويًا:

```bash
pnpm --filter @workspace/developer-portfolio run validate:projects
```

الأمر نفسه يعمل تلقائيًا عند البناء؛ إذا كان JSON أو أحد مسارات الملفات غير صالح، يتوقف البناء ويعرض موضع المشكلة بدل إنشاء نسخة ناقصة.
